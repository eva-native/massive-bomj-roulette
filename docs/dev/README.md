# Разработка

## Что нужно

- Go 1.26+
- Node.js 24+ и npm
- Docker (для PostgreSQL и сборки образа)

## Запуск

```bash
cp .env.example .env
make db          # PostgreSQL 17 в Docker, порт 5433
make dev-server  # Go-сервер на :8080, миграции применяются при старте
make dev-web     # Vite на :5173, проксирует /api и /auth на :8080
```

`make help` показывает все команды.

## Настройки (`.env`)

| Переменная | Что делает |
|---|---|
| `MBR_DATABASE_URL` | Строка подключения к PostgreSQL |
| `MBR_BASE_URL` | Публичный адрес приложения. От него зависит адрес возврата из Discord и флаг `Secure` у cookie (для `https://`) |
| `MBR_ADDR` | Адрес, который слушает сервер, по умолчанию `:8080` |
| `MBR_DISCORD_CLIENT_ID`, `MBR_DISCORD_CLIENT_SECRET` | Приложение Discord для входа |
| `MBR_ADMIN_DISCORD_IDS` | Discord ID через запятую. Эти пользователи могут создавать ивенты. Для dev-входа ID выглядит как `dev:<имя в нижнем регистре>` |
| `MBR_DEV_LOGIN` | `true` — вход под любым именем без Discord. **Только для разработки** |
| `MBR_SESSION_TTL` | Время жизни сессии, по умолчанию `720h` |

Нужен хотя бы один способ входа: Discord или dev-вход. Без этого сервер не запустится.

### Вход через Discord

1. Создайте приложение на https://discord.com/developers/applications.
2. В разделе **OAuth2** добавьте Redirect: `<MBR_BASE_URL>/auth/discord/callback`. Для локального запуска через Vite это `http://localhost:5173/auth/discord/callback`, и тогда `MBR_BASE_URL=http://localhost:5173`.
3. Скопируйте Client ID и Client Secret в `.env`.

Приложение запрашивает только scope `identify`: ник, аватар и ID.

## Тесты

```bash
make db
make test
```

Тесты с базой данных создают для себя отдельную базу на сервере из `MBR_TEST_DATABASE_URL` и удаляют её после себя. Если переменная не задана, такие тесты пропускаются. `make test-server` по умолчанию использует базу из `make db`.

## Генерация кода

После изменения SQL-запросов (`server/internal/store/queries`), миграций или типов API (`server/internal/api`) запустите:

```bash
make gen
```

- `sqlc` генерирует `server/internal/store/db`;
- `tygo` генерирует `web/src/api/types.gen.ts`.

Сгенерированный код хранится в git. CI проверяет, что он актуален.

Инструменты закреплены в отдельном модуле `server/tools/go.mod`, чтобы не тянуть их зависимости в приложение.

## Сборка и деплой

```bash
make build    # bin/mbr со встроенным фронтендом
make docker   # Docker-образ mbr
```

Продакшен через compose (приложение + PostgreSQL + Caddy с автоматическим HTTPS):

```bash
# в .env: MBR_BASE_URL=https://<домен>, MBR_DEV_LOGIN=false, данные Discord
MBR_DOMAIN=<домен> docker compose --profile app --profile prod up -d --build
```

## Устройство

- `server/cmd/mbr` — точка входа.
- `server/internal/config` — настройки из переменных окружения.
- `server/internal/store` — подключение к PostgreSQL, миграции (`goose`, встроены в бинарник), запросы (`sqlc`).
- `server/internal/auth` — вход через Discord, dev-вход, сессии. В cookie лежит случайный токен, в базе — только его SHA-256.
- `server/internal/httpapi` — маршруты `/api/*` и `/auth/*`, всё остальное отдаёт SPA.
- `server/internal/events` — ивенты, участники, роли, игры и фильмы: права и проверки. HTTP-хендлеры только переводят ошибки сервиса в коды ответа (400/401/403/404/409).
- `server/internal/api` — типы запросов и ответов, из них генерируются TS-типы.
- `server/internal/webui` — встроенная сборка фронтенда.
- `server/internal/game` — движок правил (подробнее ниже).
- `server/internal/play` — игра в ивенте: загружает снимок движка из БД, применяет действие и сохраняет его в одной транзакции под `pg_advisory_xact_lock` ивента, пишет журнал (`activity`) и шлёт уведомление в `live`. Отсюда же берутся данные для экрана хода, таблицы лидеров и очереди судьи.
- `server/internal/live` — шина уведомлений внутри процесса для SSE (`GET /api/events/{slug}/stream`). Клиент по каждому сообщению перезапрашивает то, что показывает.
- `server/internal/game/items` — каталог предметов: описание, тексты из `docs/rules`, механики.
- `web/src` — React-приложение: `api/` (клиент, хуки, типы), `pages/` (страница ивента со вкладками — в `pages/event/`), `components/`. Тесты страниц используют фейковый бэкенд из `src/test/fakeBackend.ts`.

## Движок правил (`server/internal/game`)

То, что создаёт движок (ходы, шаги, крутки, предметы, прохождения), хранится **одним `jsonb`-документом на ивент** в таблице `event_states`. Участники, игры, фильмы и настройки берутся из своих таблиц и подставляются в снимок при загрузке. Очки не хранятся: их всегда считает `Engine.Score`.

Движок работает со **снимком ивента в памяти** (`game.State`): участники, игры, фильмы, ходы, крутки, предметы, прохождения. Действие (`Spin`, `Choose`, `FinishGame`, `Use`, `SetInput`, `ConfirmGame`, `ConfirmItem`) меняет снимок по правилам. `Score` — чистая функция от снимка: очки нигде не хранятся как истина и пересчитываются целиком. Сервис загружает снимок, применяет действие и сохраняет его в одной транзакции. Тесты работают со снимком напрямую.

- **Ход** — список шагов: `spin_items × N` (или `spin_drop`) → `spin_game` → `play`. Предметы добавляют шаги (`choose_player`, вторая `spin_game`, `choose_game`, `spin_movie`). Следующий ход начинается, когда судья подтвердил итог прохождения.
- **Колёса**:
  - предметов — включённые предметы с весами ивента;
  - игр — общий пул без пройденных и брошенных игроком игр;
  - киноколесо — фильмы без просмотренных.

  `Engine.Wheel` отдаёт секторы до крутки, чтобы UI нарисовал колесо. Сектор выбирает `Picker`: в бою — `RandomPicker` (`crypto/rand`, по весам), в тестах — сценарий.
- **Предмет** (`game.Def`) — описание + `Impl`, который реализует нужные интерфейсы хуков: `Roller`, `ItemRolledListener`, `GameWheelShaper`, `GameSpunHandler`, `Attacher`, `StepDoneHandler`, `UseChecker` / `User`, `Scorer`. Каждый хук получает только разрешённые ему операции (`TurnOps`, `UseOps`, `GameWheel`, `Ledger`), так что права проверяет компилятор. Хуки не хранят состояние между вызовами: всё нужное лежит в состоянии предмета (`Self.SetState`).
- **Подсчёт:** база, скорость, рекорд или −50% за дроп, затем `Score` предметов игры по порядку: эффекты → дроп-дебаффы → бонусы. Предмет с `Blocks` выключает предметы указанных видов на той же игре, но сам не блокируется.
- **Откат** («Реролл», «Сделка») аннулирует крутку и всё, что из неё вышло: выпавшие предметы, шаги, добавленные позже, прохождение.

Как добавить предмет: простые собираются конструкторами `items.Text`, `items.FlatPoints`, `items.Blocker`; сложные — свой тип с хуками, по образцу `items/mechanics.go`. Название и текст берутся дословно из `docs/rules`. У каждого предмета должен быть сценарный тест (`items/*_test.go`, хелпер `scenario`).
