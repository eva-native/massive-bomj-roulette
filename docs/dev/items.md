# Как добавить или изменить предмет

Предмет описывается в двух местах:
- **`docs/rules/`** — название, вид и текст правила. Это единственный источник текстов.
- **`server/internal/game/items/`** — механика на Go: поля ввода, флаги, хуки.

Названия и тексты в код руками не переносятся. Их читает генератор и пишет `texts_gen.go`.

## Изменить текст правила

1. Поправить текст в `docs/rules/<вид>.md`.
2. Запустить `make gen` или `go generate ./internal/game/items` в `server/`.
3. Закоммитить и документ, и `texts_gen.go`.

CI упадёт, если `texts_gen.go` не совпадает с документами. Активные ивенты пересчитают очки при следующем действии.

## Добавить предмет

1. **Документ.** Добавить предмет в нужный файл `docs/rules/` в том же формате, что и остальные:

   ```markdown
   ### Название
   `id` · короткое описание механики

   Текст правила.
   ```

   `id` — латиница, цифры и `_`. Он попадает в базу, менять его потом нельзя.
2. **Генерация.** `make gen`.
3. **Определение** в `items/catalog.go`, в списке `Defs()`. Без него каталог не соберётся, и тест `TestCatalogMatchesDocs` упадёт.

   | Что за предмет | Как описать |
   |---|---|
   | Только правило для людей | `Text("id")` |
   | Задание с доказательством | `Text("id", WithProof())` — поле «ссылка» и подтверждение судьи |
   | Фиксированные очки | `FlatPoints("id", 4)` |
   | Отключает другие предметы | `Blocker("id", game.KindEffect, ...)` |
   | Очки по введённому результату | `def("id", Input(...), Confirm(), Impl(...))` — см. `items/results.go` |
   | Своя механика | `def("id", Impl(myItem{}))` + тип с хуками |

   Опции:
   - `Input(field(...))` — поля ввода. Типы: `bool`, `int`, `text`, `url`, `player`, `players`. Каждое поле заполняет игрок или судья (`RolePlayer` / `RoleJudge`).
   - `Confirm()` — очки только после подтверждения судьи.
   - `Lifetime(n)`, `EndsOnDrop()` — предмет действует несколько игр.
   - `OncePerPlayer()` — выпадает игроку один раз.
   - `Blocks(...)` — отключает предметы этих видов на своей игре.
   - `Use(...)` — как применяется вручную.
   - `Special(key, title)` — нужна особая игра пула.

   Бонус по умолчанию лежит в кармане и применяется к игре, как «Парашют».
4. **Механика.** Тип реализует нужные интерфейсы хуков из `server/internal/game/def.go`:

   | Хук | Когда вызывается |
   |---|---|
   | `Roller` | предмет выпал |
   | `ItemRolledListener` | у игрока выпал следующий предмет |
   | `GameWheelShaper` | перед круткой колеса игр, можно сузить колесо |
   | `GameSpunHandler` | после каждой крутки игры, можно добавить шаг или выбрать игру |
   | `Attacher` | игра выпала, предмет прикреплён к ней |
   | `StepDoneHandler` | завершён шаг, который добавил этот предмет |
   | `UseChecker` / `User` | ручное применение |
   | `Scorer` | подсчёт очков |
   | `Noter` | пометка на карточке («Часть 2») |

   Хук получает только разрешённые ему операции. Свои данные хук хранит в состоянии предмета (`self.SetState` / `self.LoadState`), а не в полях типа: хуки вызываются заново при каждом действии. `Score` должен быть чистой функцией: без случайности и записи.

   Образцы: `items/mechanics.go`, `items/game_spin.go`, `items/results.go`.
5. **Тест.** Сценарный тест в `items/*_test.go`: хелпер `newScenario` проводит ивент через движок, а сценарный `Picker` решает, что выпадет на колесе.
6. **Экран.** Обычно ничего делать не нужно: UI рисует поля ввода, кнопку применения и шаги по данным с сервера. Новый тип шага хода потребует компонента в `web/src/pages/event/play/`.

## Если правило неоднозначно

Выберите самое простое однозначное поведение и запишите его в `docs/rules/README.md`, раздел «Решения по умолчанию», чтобы его можно было пересмотреть.
